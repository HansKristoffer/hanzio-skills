# Implement

You build the change for one issue for the factory, on this thread's branch in this checkout. Research's result (its reproduction command and the checks' baseline) and, when there is one, the approved plan are under This run.

1. **Name the proof.** Read `{{skill}}/references/evidence.md` now. Its table names the proof this change needs, and the base side of that proof (a before picture, a baseline number, a base transcript) needs the code as it was: take it before your first edit.
2. **Fix the cause.** For a bug, start from research's command, which goes red. Call the Skill tool with `debug` and continue from its phase 3; with the cause already known, skip to its phase 5. Fix the cause everywhere it shows, with a regression test that failed before the fix. For a metric, call the Skill tool with `optimize` and continue from its step 5, with research's command and baseline. For a feature, build the plan's slice and nothing more.
3. **Use what exists.** The repository's own helpers and our libraries before new code. A change to production data is a `needs-decision`, never a step.
4. **Check it.** Run everything the repository's `AGENTS.md` says to run before a push, and put each command with its result in a claim, so nobody runs it again. Compare with the baseline: add no failure. A change that shows on screen is looked at in the running app.
5. **Clean it.** Call the Skill tool with `unslop` on your diff, and put every test through its authoring gate. Read the whole diff as a reviewer would.
6. **Prove it.** Finish the proof `evidence.md` names for this change, on the head: captures with `{{factory}} evidence add`, numbers in `measured`, a transcript in a claim. Put in `media` what you captured and why, or why nothing ("None: the fix has no visible effect"). Put in `tryIt` how a person tries the change in the running app: the account to sign in with, the page, the steps.
7. **Open a draft PR.** Commit with the repository's convention. Before the push, run the `land-pr` skill's `scripts/check-diff.sh --base origin/<default>` and fix every real hit. A `[secret]` hit on a made-up test value or on a variable's name is not one: leave the code as it reads best and name the hit in `notChecked`. Open a draft PR with the body from the `land-pr` skill's **Write the PR body**, under the repository's own PR template when it has one, and following what research's `notes` say the repository asks of a PR. Its Evidence holds the tests (the command, how it failed on the base, that it passes now) and any transcript. Leave out what the factory adds from your result when the PR goes ready: the reproduction, the captures, the measurements, what was not checked and what was left out. For a GitHub issue the body says `Fixes #<n>` when the PR settles all of it, and `Refs #<n>` when research left a part open. The stage ends at the draft PR: merging, marking it ready and waiting for CI are the orchestrator's.
8. **Claims.** For each plan criterion, or each thing the issue asked for, one claim with the evidence you saw: the command and its output, the test, the screenshot. What you could not check goes in `notChecked`, and choices the issue left open go in `decisions` with your confidence. What you saw beside the change and left alone (a second bug with another cause, a cleanup, something nearby the issue did not ask for) goes in `leftOut`, each with why, and stays out of the diff.

Checks still red after three fixes: return `blocked` with what you tried.
